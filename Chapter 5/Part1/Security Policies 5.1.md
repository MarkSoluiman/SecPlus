## Security Policy Guidelines 

The security guidelines should have high level strategies like data storage requirements, security event procedures, etc. They also need to have detailed security goals like appropriate Wi-Fi usage, requirements for remote access, etc.

## Information Security Policies 

This is the big list of all security-related policies. A centralized resource of processes. These policies are not just recommendations but also a mandate that is required for the organization to have and to follow.

They help organizations to answer questions when it comes to security incidents or procedures. 

## Acceptable Use Policies 

What is acceptable use of company assets. This provides what users can users are able to do with the technology provided to them. Used to limit legal liability by organizations.

## Business Continuity 

What should happen when a system or infrastructure goes down and part or all of the business can't function. 

For example, a credit card server is down that a supermarket relies on. There needs to be alternative like manual transactions, paper receipts, etc. 

## Disaster Recovery Plan

A plan to keep an organization up and running in case of disasters. Disasters can be natural, technology or system failures or human-created.

The plan should be comprehensive containing recovery location, data recovery method, application restoration, IT team and employee availability, etc.

## Incident Response Roles

Incident response team is a specialized group, trained and tested to be ready for security events.
